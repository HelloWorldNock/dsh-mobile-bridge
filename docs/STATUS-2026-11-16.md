## 3. 能力基线

- **连接**：UDP 自动发现（含 NAT 虚拟机中继 48126）、手动配对、多主机并存、局域网 ↔ tailnet 自动选路、内嵌 tsnet（PC 端 `tsnode`、手机端 `gobridge.aar`，不占系统 VPN）。
- **任务**：工作区折叠分组、搜索、新建（工作区/prompt/计划模式/权限预设/最多 4 张图）、流式回复、停止、重命名、彻底删除、归档/取消归档（与桌面端共用 registry 集合）。
- **交互**：审批与提问双端同时下发，先答为准；plan-review 断线保卡；通知动作可直接允许/拒绝；运行日志双端导出。
- **协作**：绑定组 + 组密钥 + 协作工作区，组内 `delegate` 委派（默认 240 s，可续跑），产物只落对端协作工作区。
- **图片**：发送侧压到长边 1600 / ≤3.5 MB；时间线回显原始字节（`/api/sessions/:id/images/:seq/:index`，主机 256 条引用 LRU、手机 24 MiB LRU）。

## 6. 缺口与风险

**R1 插件包落后源码（交付阻塞）**。`dist/dsh-mobile-bridge-0.8.8.tgz` 内文件与当前源码不一致：`client.js` 56,055 vs 56,468、`events.js` 12,854 vs 14,293、`history.js` 2,799 vs 4,517、`dto.js` 7,808 vs 8,074。用它装到别的机器，会退回到「手机打不开子代理会话 / 新建工作区是空壳 / 面板挂错插槽」的状态。

**R2 版本号承载了两批改动**。0.8.8 同时装了归档和 0.2.x 适配，release note 只描述归档；外部用户看不出为什么必须升级。另外 `host/lib/index.js:25-27` 的 `DEFAULTS` 超时是 30/60/120 s，而 `state.js` 默认 120/120/180 s（README 写的是后者），只有配置显式传非法值时才落到前者——两处默认值该统一。

**R3 测试从未入库**。`.gitignore` 里 `test/` 没有锚点，把 `host/test/` 一起忽略了：`git ls-files host/test` 为空、`git log -- host/test` 无记录。换机器 clone 后 `npm test` 跑的是 0 个用例，而 README 第 288 行声称「101 个 host 测试全部通过」。这是当前唯一没有回归保护的地方。

**R4 发布链路断在 0.8.4**。tag 只有 v0.1.0 / v0.6.1 / v0.8.4，0.8.5→0.8.8 无 tag；`contrib/` 的 `tarball` 与 `version` 仍指 0.8.3（`awesome-dsh-plugin/dsh-mobile-bridge.yml:11`、`dshmarket/plugins.json:21-22`）。手机/面板的「检查更新」比的是 GitHub 最新 release，0.8.5 之后的用户拿不到更新提示。本次 GitHub API 查询无响应，发布页实际状态未在线核实。

**R5 README 落后于功能**。缺 0.8.6 的时间线图片回显与全屏查看、默认工作区目录；缺 0.8.7 的双端运行日志导出与 plan-review 断线保卡；缺 0.8.8 归档语义与 0.2.x 适配说明。

**R6 已知限制仍然有效**（`README.md:346` 起）：手机 token 明文存 SharedPreferences（Keystore 未做）、应用层明文 HTTP（靠 Tailscale 隧道加密）、不支持 iOS / 模型切换 / fork / always-allow、内嵌节点仅 arm64-v8a 与 x86_64、工具参数与结果在手机上截断（正文 4000 字 / 参数 800 字）、取消归档目前只能在电脑上做。
