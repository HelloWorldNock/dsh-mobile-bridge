## 1. 项目目标与技术栈

**目标（从 README 与代码行为归纳）**：让 Android 手机在局域网或 Tailscale tailnet 内远程驱动 DeepSeek Harness —— 看任务、发 prompt（可带 4 张图）、审批工具调用、审阅计划、收通知、归档会话，并可与另一台 PC 组队派活。手机端**不实现** DSH 的 Typert 协议，只走精简 JSON + SSE。

### 1.1 架构

```
Android App (Kotlin + Compose, 36 个 .kt / 7,894 行 / 354 KB)
   │  HTTP/JSON + SSE，Bearer dshm_…；局域网优先 → tailnet 兜底
   ▼
dsh-mobile-bridge（DSH host bundle，18 个 ESM 模块 / 6,074 行；0.0.0.0:48123，UDP 48124/48126）
   │  直调 ctx.sessionController / sessions / workspaceRegistry / approval / userQuestions
   ▼
DSH Desktop（本机以 junction 直链源码：profiles\desktop\node_modules\dsh-mobile-bridge → host\）
```

| 层 | 技术选型 | 证据 |

### 5.1 端口与鉴权模型

### 5.3 SSE 事件（实测集合）

`hello`（连上首帧）、`session.snapshot|event|added|updated|status|activity|removed|error`、`assistant.delta`、`approval.requested|closed`、`question.requested|closed`、`notice`。共 12 个广播名 + `hello` 帧；**无 `resync`**。

### 5.4 五条关键数据流

**① 配对**
面板 `POST /api/setup/code` → 6 位码（120 s）→ 手机 `POST /api/pair {code, device}` → 服务端生成 `dshm_`+32B、只存 SHA-256 → 手机把 `{baseUrl, token, deviceId, endpoints}` 写入 SharedPreferences（JSON，明文）。

**② prompt 与流式**
手机 `POST /api/sessions` 或 `POST /api/sessions/:id/prompt {text, images[]base64}` → host 组装 `content[{type:'text'},{type:'image'}]` → `ctx.sessionController.prompt()` → 宿主事件 → `hub` follow → `dto.projectEvent` 投影 → `broadcast` 推 `assistant.delta` / `session.event` → 手机 60 ms 合并上屏。

**③ 审批双端**
宿主 waterfall 请求 → `handleApproval` 建手机卡片并广播 `approval.requested` → 同时 `callNext()` 交给桌面 →
手机先答：返回结果并给已转发的桌面事件下发 `cancel` 帧（桌面 `request.signal` abort 自行撤卡）；
桌面先答：广播 `approval.closed {answeredBy:'desktop'}` → 手机撤卡；
手机断线：卡片保留在 `/api/pending` 等重连。

**④ 归档对账**
桌面写 `workspaceRegistry.archivedSessionIds`（无事件）→ `events.js` 每 3 s 比对签名 → 新增→`session.removed{archived:true}`（同时丢 summary、停 follow）；移除→`session.added`；接口写完归档立即主动对账一次。

**⑤ 组内 delegate**
本机 agent 调 `collab` 工具 → `group` 找到 peer baseUrl → `POST /api/sessions`（带 `workspaceId`/`cwd`）→ 轮询到结束 → 回传 `{status, sessionId, reply, files}`；`fetch` 再拉单文件落本地。

### 5.5 数据落点与敏感度

| 位置 | 内容 | 敏感度 |
|---|---|---|
| `%DSH_HOME%\storages\mobile-bridge\state.json`（4,704 B） | deviceId、hostName、11 条设备（**仅 `tokenHash`**）、group、peers、settings（含 `workspaceRoot`、`collabRoot`、`tailscaleHostname/StateDir`；本次 `tailscaleAuthKey` 为空） | 高（勿外发） |
| `...\mobile-bridge\logs\bridge.log`（37,887 B） | 环形 + 落盘日志 | 中（可能含路径/主机名） |
| `host\.tsnet-state\` | tailnet 节点密钥（已 gitignore） | 高 |
| Android SharedPreferences `dsh_remote` | `hosts` JSON 含 **token 明文**、`activeHostId` | 高（Keystore 未做） |

## 8. 范围边界与待决策项

### 8.1 明确的范围边界（现状事实，非建议）

- **平台**：仅 Android（minSdk 26 / target 35），无 iOS；PC 侧仅 Windows 已交付 tsnode 二进制，其他平台需自行 `build-tsnode.ps1`。
- **能力不做**：模型切换、fork、子代理控制、always-allow、公网端口映射、跨 NAT 自动打通。
- **网络信任模型**：桥接监听 `0.0.0.0`、应用层明文 HTTP，安全性依赖"同一局域网"或"Tailscale 隧道"；不做 TLS。
- **协作组信任模型**：拿到组密钥的机器可在本机建会话、写 prompt、读协作工作区文件（不能读 `/api/events`、不计为"手机在线"）；组内成员互信，无细粒度授权。
- **数据边界**：`/api/collab/file(s)` 只读协作工作区内部，越界/软链一律 403；单次 200 文件 / 64 MB。
- **交付形态**：debug 签名、双 ABI 单包、插件包内含未签名 22 MB exe（会被安全软件拦）。
