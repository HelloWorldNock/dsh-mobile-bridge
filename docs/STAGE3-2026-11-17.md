## 第二轮（同一阶段，R21 第一刀）

- 搬走的都是**纯规则**：`promptContent`（图片数量/类型/base64/单张与总量上限）、`cleanTitle`、
  `validTimeZone`、`fileStamp`、`clampLogLines`、`toEpochMillis`、`samePath`、`cleanFolderName`。
  以前这些只能通过整条 HTTP 请求间接覆盖，现在有 11 条直接断言（含 8 MiB 单张上限与 4 张上限）。
- 路由族按「注入 `api`、返回 `handled: boolean`」的模式拆：`createWorkspaceRoutes({sendJson,
  readJson, workspaceList, workspaceRoot, archivedSessionIdSet, workspaces})`。这样模块不需要知道
  `createBridgeServer` 的闭包，鉴权仍留在 server 里，`BridgeError` 仍由统一 catch 映射。
- 行为不变：`GET /api/workspaces` 仍过滤归档会话并回传 `archivedSessionIds`；`POST` 仍先
  `resolveByPath` 再决定建目录，失败码（`workspace/no-root|bad-name|exists|create-failed|unavailable`）不变。

## 第三刀：设置路由族（R21 续）

- `lib/routes/setup.js` 承接 `/api/setup/*`，把「只允许 loopback」「POST 必须 CSRF」写在模块入口，
  任何具体动作之前先过这两道——面板的安全边界不依赖调用方记得检查。

  与 tailscale 六种动作的映射。

## 本轮改动细节

### 适配层为什么值得先做

`server.js` 里原本散着 33 处 `ctx.sessionController.*` / `ctx.workspaceRegistry.*`，每处都自带
`typeof === 'function'` 判断和 try/catch，宿主一变签名就得全仓找。收进适配层之后：

- 形状差异只在一处：`list()` 吃 `{items}` 与裸数组；`resolveByPath()` 统一 `await`（0.2.x 是异步）。
- 语义差异只在一处：`archivedIds()` 返回空集合（列表接口不能因为读不到就清空），
  `archivedIdsOrNull()` 返回 null（事件轮询要保持基线）。
- 写操作异常**不吞**：`WorkspaceActiveSessionError` 仍是 server 映射 409 的依据。
